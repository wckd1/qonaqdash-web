QonaqDash design system

Design system — This gallery plus src/assets/main.css define top-level visuals (tokens, shared layout, reusable components). Sections run small → large: foundation, compact parts, composite controls and page chrome, then full structures.

Page specification — Routes, templates, and flows live in design.md, using the naming and classes documented here. Product UI implements those pages and adds route-scoped styles only where needed; repeated scoped patterns should be proposed for promotion into this system, then views refactored to shared classes.

Backend / HTTP — High-level integration: integration.md. Endpoint details (routes, schemas, errors): swagger.yaml (OpenAPI).

Form-level vs field-level

.form-error, .form-info, .form-success are whole-form or page-level banners. .form-field-error sits under a single control. Field stacks and control chrome use the same tokens as Form layout (--form-element-padding-*, --control-bg, --control-border, --control-focus-ring).

Search bar

Semantic <search> with icon, text field, and clear control; .has-value toggles the clear affordance. On list screens, place as a direct child of main.app-main under the page header. Shell placement: Page layout & search.

Page layout & search

Main content column (main.app-main): optional breadcrumbs, header.page-header (title + actions), then body. List template: search or .search-bar-wrap under the header, then section.list-content. Interactive search pattern: Search bar. Outline header CTA: Page header (outline CTA). Detail / schema-driven screens often skip the list wrapper; use inner sections for the form. Selectors: main .page-header, main.app-main > section.list-content in main.css.

Empty state

Full-parent centered placeholder for lists, grids, and sections with no data. Container: .empty-state-widget (fills parent width & height, flex-centers content). Slots: __icon (contextual SVG in a tinted circle), __title, optional __description, optional __actions (vertical button stack). Place inside any scroll root or content area (.list-content__viewport, .dashboard-view__viewport, etc.).

Lists & tables

section.list-content + scrollable .list-content__viewport. Table .list-table; row classes .list-row, .list-row--selected. Row actions (embedded tables, not whole-row click lists): trailing column th.list-table__col--actions (often blank) / td.list-table__cell--actions — text-align: right pins the cluster to the row’s right; wrap multiple controls in .list-table__actions (inline-flex row). Text: .list-table__action on links (<a>) or <button>. Icon buttons: .list-table__icon-btn + --brand / --danger / --success (include aria-label). When rows are clickable, stop propagation from the actions cell so controls do not trigger row selection.
